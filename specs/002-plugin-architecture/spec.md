# Feature Specification: 可独立演进的插件架构

**Feature Branch**: main
**Created**: 2026-09-15
**Status**: 目标设计，规格质量 16/16。当前交付结果见 [插件运行时](../../docs/plugin-runtime.md)。

## User Scenarios & Testing

### User Story 1 - 独立插件交付 (Priority: P1)

维护者通过插件产物、清单及配置提供平台、模型、语音、记忆和工具能力。核心及其他插件产物保持固定。

验收结果：插件安装后具有正式业务能力；停用和移除后资源归零、持久数据保留；空插件宿主提供管理、鉴权、诊断及准确 readiness。

### User Story 2 - 身份与状态连续 (Priority: P1)

同一公开契约的候选实现具备独立替换资格，人物身份、经历、关系、账号和工作凭证完整保留。

验收结果：当前请求对应活动代次，在途工作对应自身快照；候选资格以初始化、配置和数据核验为依据；恢复保留已确认状态，代码替换采用声明的生效方式。

### User Story 3 - 生命周期具有确定结果 (Priority: P1)

每个插件具有目标状态、实际状态、依赖、资源及诊断。管理竞争形成唯一持久提交，宿主恢复具有唯一活动实例。

验收结果：每个生命周期状态可定位，控制预算明确，资源清理具有完整凭证，其他能力保留可用状态。

### User Story 4 - 配置、授权与依赖独立 (Priority: P1)

插件作者使用当前能力契约和受限端口；配置、权限及隔离各有独立归属。

验收结果：激活资格包含有效配置、必需能力、授权范围和隔离条件；配置更新保留最近有效快照；人物、账号及受众各有可信范围。

### User Story 5 - 既有业务连续 (Priority: P2)

新边界保留 QQ、私聊、记忆和直播的实际行为。路由以 AI、账号或能力为范围，外部副作用对应唯一活动路径。

验收结果：同样输入的确定性归属、引用、白名单、作息和记忆归并一致；最终交付通过独立正式产物验收。

## Requirements

### Functional Requirements

- **FR-001**: 插件添加、移除、替换、启用、停用和升级由该插件产物与配置完成，核心及其他产物保持固定。
- **FR-002**: 核心依赖集合为稳定公开契约，内置及外部插件采用同一能力接口。
- **FR-003**: 空插件核心提供管理、配置诊断和健康，业务 readiness 对应实际能力集合。
- **FR-004**: 插件、实例、作用范围和能力绑定具有各自稳定标识。
- **FR-005**: 清单包含提供/消费能力、配置 schema、权限、隔离和状态交接声明，激活资格明确。
- **FR-006**: 依赖以能力契约解析，必需、可选、冲突及环具有确定结果。
- **FR-007**: load、init、start、stop、dispose、unload 各有适用条件、完成标准和资源结果。
- **FR-008**: 重复管理请求对应同一操作，实例及依赖变更具有一致并发控制和持久记录。
- **FR-009**: 停用完成表示入口闭合、在途工作完成或明确中止、执行资源释放。
- **FR-010**: 替换资格由候选核验与单写者交接确定，新请求对应已提交活动代次。
- **FR-011**: 插件变更保留身份、记忆、关系、消息、账号归属和工作恢复凭证。
- **FR-012**: 有状态实现提供对应交接和恢复结果，数据确认是切换资格。
- **FR-013**: 配置按插件及实例隔离，具有覆盖语义、有效快照和修订；秘密归受限资源。
- **FR-014**: 当前公开契约是插件装载及实现替换的唯一接口标准。
- **FR-015**: 人物、账号、会话、受众和动作权限由可信运行上下文及当前授权确定。
- **FR-016**: 工具访问范围为获准业务数据和动作，消息删除、账号资料维护及凭据管理归人工管理权限。
- **FR-017**: 插件隔离匹配信任、依赖及资源要求，代码生效方式与宿主影响可见。
- **FR-018**: 外部调用具有 deadline、有限重试、并发及积压预算，unknown 具有查询或核实结果。
- **FR-019**: 诊断关联插件、实例、配置、阶段及业务事件，指标和恢复入口使用脱敏资料。
- **FR-020**: 能力及声明式界面由扩展点提供，停用结果包含入口撤销与历史诊断保留。
- **FR-021**: 迁移以明确业务范围为单位，旧包装器具有退出标准，副作用属于唯一活动路径。
- **FR-022**: QQ 优先级、NapCat 登录态、白名单、人物连续性、受众、消息顺序及记忆归并保持一致。
- **FR-023**: 每个实际插件通过公开管理及业务入口形成六种独立变更证据，产物验收采用正式安装包。
- **FR-024**: 状态交接采用明确所有权、可移植快照和公开数据契约。
- **FR-025**: 管理入口提供鉴权、预检、影响范围和操作状态，执行范围对应用户授权。

### Key Entities

插件产物具有 ID、位置、摘要及声明；实例具有宿主、scope、状态与资源；绑定对应能力与活动实例；配置及授权具有修订；交接资料包含所有者、水位和工作凭证；操作记录包含操作者、标识、状态及恢复依据。

## Success Criteria

- **SC-001**: 每个交付插件完成六项变更验收，核心及其他插件产物摘要保持原值。
- **SC-002**: 空插件、物理移除及独立依赖环境的管理启动成功率为 100%。
- **SC-003**: 生命周期边界场景中，其他能力确定性请求成功率为 100%，动作具有唯一授权结果，已确认状态完整保留。
- **SC-004**: 每个插件 100 次启停后，任务、订阅、定时器、句柄及 worker 资源回到基线。
- **SC-005**: 固定输入、模型响应与授权条件下，人物、账号、会话、引用、白名单、作息及记忆断言一致率为 100%。
- **SC-006**: 本地 2 AI、20 会话、每秒 10 事件、15 分钟，排除供应商等待后的 P95 增量 ≤max(基线×10%,20ms)，模型调用及 token 量至多等于基线。
- **SC-007**: 控制结果在 30 秒内明确，排空预算 60 秒；状态恢复 ≤5 分钟，已确认持久状态 RPO=0。
- **SC-008**: 替换、升级及恢复保留完整状态归属，成功记录具有数据核验依据。

## Assumptions

目标为 31 个独立插件包，当前实现能力见运行时文档。Memory 是可信 ai-agent 进程内插件，代码替换允许声明的宿主重启。基础设施及登录外壳具有稳定归属。音乐、Avatar、Stream 的业务结果沿用现有指令记录和事件回调范围。

SC 指标是目标值，实际状态由独立验收证据表达。详细设计见 [architecture.md](architecture.md)，验收标准见 [acceptance.md](acceptance.md)。
