# Feature Specification: 可独立演进的插件架构

**Feature Branch**: `main`（本次未创建或切换分支；规格目录与分支独立）

**Created**: 2026-09-15

**Status**: Draft — 需求质量检查通过，可进入规划；尚未实施

**Input**: User description: "Refactor my existing project using a plugin-based architecture. Every plugin can be added, removed, replaced, enabled/disabled, and upgraded independently without changing the core. The core must depend only on stable interfaces/contracts, never on any concrete plugin. Provide boundaries, contracts, lifecycle, configuration/permissions/isolation/errors, directory structure, migration plan and acceptance checklist. Don't need plugin version and compatibility."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 增删插件不改核心 (Priority: P1)

维护者安装或移除平台、模型、语音、记忆或工具能力，只调整该插件及其配置，不修改或重新发布核心和其他插件。

**Why this priority**: 这是用户提出的硬性要求，决定后续扩展是否真正独立。

**Independent Test**: 固定核心发布产物，使用独立交付插件，通过正式管理入口完成安装、启用、停用、移除，并验证未受影响能力和空插件启动。

**Acceptance Scenarios**:

1. **Given** 固定版本核心和独立插件，**When** 安装并启用插件，**Then** 对应能力可通过业务入口使用，核心和其他插件源码及发布产物摘要不变。
2. **Given** 插件正在运行，**When** 停用后移除，**Then** 新调用不可进入该插件，任务、订阅、资源与界面入口撤销，未受影响能力继续可用。
3. **Given** 所有插件均未安装，**When** 启动核心，**Then** 管理与诊断可用，业务能力准确显示缺失，不尝试加载缺失插件或其依赖。
4. **Given** 业务流程需要的唯一能力被移除，**When** 收到相关请求，**Then** 明确报告不可用或按声明延后处理，不伪造成功，其他流程不受牵连。

---

### User Story 2 - 替换升级后身份与状态连续 (Priority: P1)

维护者用遵循当前公开契约的实现替换或升级现有插件，保留人物身份、历史经历、关系、账号归属和未完成工作；不引入插件版本管理或兼容性机制。

**Why this priority**: AI-Love 的价值依赖持续状态，不能因插件化重置人物或重复行动。

**Independent Test**: 在消息和记忆实际入口存在在途任务时切换插件，验证失败回退、重启恢复和持久数据一致性。

**Acceptance Scenarios**:

1. **Given** 同一能力存在两个遵循当前契约的实现，**When** 按范围切换绑定，**Then** 新请求进入新实现，在途工作遵循排空规则，账号和回复对象不变。
2. **Given** 候选实现不能初始化或读取现有状态，**When** 尝试升级，**Then** 保留正常实现，返回原因及恢复步骤。
3. **Given** 替换后的实现已写入数据，**When** 需要故障恢复，**Then** 按该次变更的数据恢复步骤执行，保留已确认状态，不以切回旧代码代替恢复数据。
4. **Given** 插件声明需要重启宿主才能更换代码，**When** 升级，**Then** 预先报告影响范围，在受控窗口恢复，核心和其他插件无需修改或升级。

---

### User Story 3 - 生命周期可控且故障可定位 (Priority: P1)

运维人员查看每个插件的目标状态、实际状态、依赖和错误，并安全停止故障插件。

**Why this priority**: 后台扫描、主动发言和持久消息需要明确的停止边界。

**Independent Test**: 通过管理入口逐阶段注入故障，观察资源回收和无关插件的可用性。

**Acceptance Scenarios**:

1. **Given** 插件经历加载、初始化、启动、停止、释放、卸载，**When** 任一步失败或超时，**Then** 显示失败阶段、未清理资源和下一步。
2. **Given** 两名维护者同时变更同一插件，**When** 请求竞争，**Then** 只提交一个一致的变更，另一个请求得到冲突结果。
3. **Given** 插件持续故障，**When** 超过时间或资源预算，**Then** 阻止新工作并限制重试，无关插件继续服务。
4. **Given** 宿主在切换中退出，**When** 重启，**Then** 根据持久操作记录恢复一个活动实例，不允许两个实例执行相同外部动作。

---

### User Story 4 - 配置、授权和能力依赖独立管理 (Priority: P1)

运维人员分别管理插件配置与权限；插件作者只使用公开契约，不访问核心内部对象。

**Why this priority**: 避免将实现耦合转移到配置、数据或权限上。

**Independent Test**: 提交缺失必需能力的插件、无效配置、越权与跨人物请求，验证拒绝结果且原实现仍可用。

**Acceptance Scenarios**:

1. **Given** 必需能力缺失或配置无效，**When** 激活，**Then** 在接受业务请求前拒绝并列出原因。
2. **Given** 插件请求人物或账号数据，**When** 超出授权范围，**Then** 拒绝并审计，模型输出和插件配置不能扩大授权。
3. **Given** 已有有效配置，**When** 收到无效或乱序更新，**Then** 保留最后有效配置并报告错误，不停止所有插件。
4. **Given** 插件需要冲突的依赖或不被信任，**When** 安装，**Then** 使用符合声明的隔离方式，不能修改核心依赖或扩大权限来迁就。

---

### User Story 5 - 渐进迁移现有行为 (Priority: P2)

维护者逐项把旧实现接入插件边界，按人物、账号或能力切换，异常时恢复旧路径。

**Why this priority**: 保留 QQ、私聊、记忆和直播链路，避免一次性重写。

**Independent Test**: 同一批脱敏输入比较旧路径与新路径的决策、状态归属和发送结果，仅活动路径产生副作用。

**Acceptance Scenarios**:

1. **Given** 旧实现已包装，**When** 仅切换一个账号或人物，**Then** 其他范围保持原路由，指标可以分别比较。
2. **Given** QQ 和记忆已迁移，**When** 处理私聊、群聊、引用和静默期记忆，**Then** 保留白名单、24 小时被动回复、主动作息、受众边界和批处理语义。
3. **Given** 迁移完成，**When** 移除全部临时迁移包装器和停用插件包，**Then** 核心仍启动，已迁移能力无需旧源码、注册表或供应商依赖。

### Edge Cases

- 重复插件标识、能力多提供者但无绑定、必需能力缺失、依赖成环、可选依赖恢复。
- 停用、权限撤销、配置更新、升级同时发生，旧请求持有旧实例引用。
- 停止超时、部分初始化、资源残留、宿主突然退出、切换后旧实例重新连接。
- 平台接受发言但确认丢失：结果未知，不能盲目重发。
- 新实现写入旧实现不能读取的数据；移除或禁用不得顺带删数据。
- 记忆停用期间积压达到容量上限，恢复时不得静默丢失人物经历。
- 缺少图片、语音或直播能力，只能按声明降级，不能声称已理解未处理内容。
- 插件界面被移除但旧浏览器页面仍持有过期入口。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 每个插件 MUST 独立添加、移除、替换、启用、停用、升级；不得要求修改核心或其他插件源码、发布产物或依赖版本。允许调整插件清单、配置、授权和绑定。
- **FR-002**: 核心 MUST 只依赖稳定公开契约，不得通过直接、间接、条件分支、默认实例或打包依赖绑定具体插件；内置插件和外部插件遵守同一规则。
- **FR-003**: 核心 MUST 在零插件状态提供管理、配置诊断和健康信息，区分核心存活与业务可用；缺少能力时明确暂停相关业务。
- **FR-004**: 系统 MUST 分别标识插件、运行实例、启用范围和能力绑定，隔离不同人物和账号状态；不要求插件版本字段。
- **FR-005**: 插件 MUST 声明提供和消费的能力、配置格式、权限、隔离要求及状态交接方式；激活前校验配置、必需能力和生命周期入口。
- **FR-006**: 系统 MUST 以能力契约而非具体插件身份解析依赖，检查必需/可选关系、冲突和环；移除时仅阻断或切换确实受影响流程。
- **FR-007**: 系统 MUST 提供有前置条件、完成条件及失败清理规则的 load / init / start / stop / dispose / unload 过程，记录期望和实际状态。
- **FR-008**: 生命周期操作 MUST 可重复提交而不重复副作用；同一实例及相关依赖切换必须有一致的并发控制和持久操作记录。
- **FR-009**: 停用 MUST 先阻止新工作，再排空或有界中止在途工作，最后释放任务、订阅、连接、界面贡献和临时资源；不能误报卸载完成。
- **FR-010**: 升级替换 MUST 先验证候选，再一致地切换新请求并清理旧实现；持久写入和外部动作不得由新旧实例同时执行。
- **FR-011**: 插件变更 MUST 保留身份、记忆、关系、消息、账号归属和未完成工作恢复信息；数据删除是独立操作。
- **FR-012**: 有状态插件 MUST 提供本次变更所需的数据移交和恢复步骤；不能把回退代码等同于恢复数据，数据交接失败时不得提交切换。
- **FR-013**: 配置 MUST 按插件和实例隔离，明确覆盖、校验和修订规则；失败保留最后有效配置，凭据不得出现在正文、日志或导出中。
- **FR-014**: 系统 MUST 使用一套当前公开契约，不实现插件/API/配置/状态版本管理、版本协商、兼容矩阵、多版本支持或自动兼容转换；升级通过替换插件实现完成。
- **FR-015**: 系统 MUST 默认拒绝未授权操作，校验人物、账号、会话、受众和动作范围并支持撤销；依据来自可信上下文，不是模型或插件自报。
- **FR-016**: 工具 MUST 始终不能删除消息、修改账号资料、读取或导出凭据；供应商连接凭据与工具可用数据隔离。
- **FR-017**: 系统 MUST 按信任、依赖冲突和资源风险实施隔离，不具备条件的插件不得激活；共享环境限制和重启影响预先可见。
- **FR-018**: 外部调用 MUST 有超时、有限重试、并发和积压上限；有副作用的未知结果必须查询或交由人工处理，不可盲目重放。
- **FR-019**: 故障 MUST 关联插件、实例、配置修订、处理阶段及业务事件，提供健康、指标、审计和恢复步骤，避免记录敏感正文。
- **FR-020**: 新增能力及可选管理界面 MUST 通过扩展点声明，无需修改核心注册列表、路由、页面分支或供应商配置类型；停用后撤销入口并保留历史诊断。
- **FR-021**: 迁移 MUST 支持旧实现包装、按范围切换、受控比较和逐步退役，每阶段定义验收和回退条件；任何时间一个动作只能有一个活动执行路径。
- **FR-022**: 迁移 MUST 保持业务边界、QQ 优先顺序、NapCat 登录态和白名单，保持人物连续性、受众隔离、消息顺序和现有记忆归并链路。
- **FR-023**: 每个插件 MUST 通过公开管理和业务入口验证六种变更，包括同契约替代者、空插件宿主和正式安装包测试；孤立内部方法测试不能替代。
- **FR-024**: 实现间状态交接 MUST 使用明确数据所有权及可移植格式，不要求替代者导入旧实现或读取未公开私有表。
- **FR-025**: 管理入口 MUST 鉴权并提供预检、影响范围和操作状态；本次只编写本地规格与设计，不部署或修改外部配置。

### Key Entities *(include if feature involves data)*

- **插件发布物**：具有标识、产物位置、摘要及声明的独立能力实现；摘要用于确认交付内容，不用于版本选择。
- **插件实例**：特定宿主、人物或账号范围的运行实体，具有状态和资源归属。
- **能力契约**：当前稳定的输入、输出、错误和行为约定，可由多个实现提供。
- **绑定**：业务范围的能力需求到活动实例和代次的映射。
- **配置快照与授权**：当前生效配置、用于并发控制的修订标识及可信管理者授予的访问范围。
- **状态交接记录**：数据格式、所有者、水位、在途工作与恢复依据。
- **变更操作记录**：操作者、请求标识、阶段、结果和补偿状态。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 每个交付插件完成六项独立变更验证，核心和未变更插件发布产物摘要变化数为 0。
- **SC-002**: 零插件、物理移除插件文件和供应商依赖不存在三种环境，管理与诊断启动成功率均为 100%。
- **SC-003**: 每个生命周期阶段及切换提交前后发生故障的验收场景，无关能力的确定性请求成功率为 100%；越权、重复外部动作、已确认持久状态丢失均为 0。
- **SC-004**: 每个插件完成 100 次启停后，其活动任务、订阅、定时工作和资源句柄回到基线；隔离进程退出后无遗留子进程。
- **SC-005**: 相同脱敏输入、模型响应和授权下，迁移前后人物/账号/会话归属、回复目标、白名单、作息和记忆归并的确定性断言一致率为 100%。
- **SC-006**: 本地验收基线为 2 个人物、20 个并发会话、10 条入站事件/秒、持续 15 分钟。排除外部供应商耗时后，端到端 P95 处理延迟增加不超过 10% 或 20 毫秒中的较大值；每场景模型调用次数和输入输出 token 总量不增加，非注入故障错误率为 0。
- **SC-007**: 默认控制阶段在 30 秒内完成或返回明确失败，停止排空预算为 60 秒；有状态恢复演练在 5 分钟内恢复，已确认持久状态丢失为 0。尚未持久接收的外部事件不计入保证，必须单独测量。
- **SC-008**: 每次升级、替换和故障恢复保留身份、关系、历史消息及记忆归属；状态导入或恢复失败时误报成功数量为 0。

## Assumptions

- 按用户最新要求，移除插件版本及兼容性机制。插件作者负责遵循当前公开契约，运行时不维护历史接口或自动适配；仍保留必要的配置校验、资源清理和数据保护。插件升级是替换实现，不是由核心选择版本。
- 本次 `$speckit-specify` 交付需求、架构建议和迁移路线，未实施生产重构。技术细节见 [architecture.md](architecture.md)，执行验收见 [acceptance.md](acceptance.md)。
- “独立”要求核心和其他插件无需改动或联动升级，允许变更清单、绑定与授权。未要求所有插件零停机热升级；需要重启的插件必须事先声明影响，不满足依赖和隔离条件的升级应拒绝。
- 沿用宪章 1.3.0 的运行单元、配置体系和迁移约定；可信 Memory 保持 ai-agent 进程内。隔离工作进程不默认新增微服务。
- 可变业务实现纳入插件边界；稳定人物标识、受众和授权规则、消息协调、数据所有权与管理控制归核心。基础设施部署和登录鉴权机制替换不属本次范围。
- 移除插件不等于保留其业务功能；必需能力缺失时暂停相关业务，管理仍可运行。
- 仅为现有变化点定义首批契约，不预建游戏引擎或任意代码界面市场；首期界面使用受限声明式贡献。
- 规划核查确认音乐播放器、Avatar/Stream 的真实外部执行尚未接通；本次迁移现有能力，未实现动作明确返回 unsupported/unavailable，不把日志记录当作成功执行，不隐含扩展业务范围。
- 指标为拟定验收目标，并非实测值；规划阶段记录机器规格、依赖版本与基线，上线前在目标环境复验。
- 工作区有私聊等未提交修改，分析以 2026-09-15 工作区为准；现有测试是回归素材，不能推断已经通过生产验证。
