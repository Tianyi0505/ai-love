## 执行规则

每个实际插件分别复制一份结果记录。先固定核心、契约 SDK 和未变更插件的产物摘要及依赖锁；使用正式 wheel/worker 产物，不挂载项目源码。操作走公开管理入口，业务走该插件实际入口。仅修改绑定或测试替身无法证明物理移除和独立发布。

每项记录：插件 ID/产物摘要、实例范围、核心/SDK 摘要、配置及权限修订、环境、入口、操作 ID、预期与实际、日志/状态证据、模拟边界、结果。`[x]` 只在证据完整时勾选，不能把“设计支持”视为“运行通过”。

## A. 六项硬要求（对每个插件执行）

| 操作 | 正式入口动作 | 必须观察到的结果 | 需求 |
|---|---|---|---|
| 添加 | 核心在未安装该插件时启动 → 安装独立产物 → 配置绑定 | 不改核心/其他插件源码、发布物、依赖锁；能力可被发现并通过业务入口调用 | FR-001/002/023 |
| 移除 | 通过管理器停用/卸载 → 物理移除包文件与独占依赖 → 再启动 | 无旧包仍启动；无旧路由/任务/订阅/页面；持久数据保留 | FR-001/003/009/011 |
| 替换 | 安装不同插件 ID 的同契约实现 → 状态移交预检 → 切换绑定 | 新请求到替代者；无需旧插件实现或私有表；不重复动作、不串人物 | FR-010/012/024 |
| 启用 | 已安装但禁用 → 启用一个实例范围 | 仅该范围能力就绪；资源登记可见，其他账号和人物不变 | FR-004/007/008 |
| 停用 | 持续真实业务输入与后台任务中停用 | 阻止新工作，排空或明确中止，资源回到基线；相关业务准确降级/暂停 | FR-006/009/018 |
| 升级 | 仅安装该插件新实现本/独立依赖 → 候选预检 → 交接 | 核心与无关产物摘要不变；状态完整，旧实例回收；需要宿主重启时按预告窗口执行 | FR-001/010/012/014/017 |

- [ ] ACC-001 每个实际插件的上述六格均有独立证据，任一失败不得称为“真正可插拔”。
- [ ] ACC-002 删除全部插件后核心管理、鉴权与诊断可运行，业务 readiness 明确为缺失；没有自动导入/实例化供应商。
- [ ] ACC-003 核心及 SDK 的直接和传递依赖不含具体业务插件/供应商实现；源码无具体插件 import、包名分支、默认实例或类型注解泄漏。
- [ ] ACC-004 通用宿主、构建脚本、配置校验、中央注册表、数据库 migration 和前端路由不因添加同契约插件而改动。
- [ ] ACC-005 新插件在单独工作目录仅依赖 SDK/公开端口构建和验证，不能使用仓库源码路径或其他插件的可编辑安装。

## B. 契约、依赖和配置

- [ ] ACC-006 用每项实际扩展点的不同实现替换；不只用 echo 假插件测试统一调用方法。可使用专门编写的同契约实现，但必须经正式发布和业务入口验证，并标明其测试用途。
- [ ] ACC-007 通过正常发布清单构造重复 ID、多候选无绑定、缺失必需能力、依赖环和无效配置，均在开放业务前拒绝并展示具体原因。可选能力缺失只触发声明的降级。（FR-005/006/014）
- [ ] ACC-008 同一插件同时运行两个账号/AI 实例，更改单个实例配置、停用其中一个，不串用连接、缓存、人物或账号归属。（FR-004/015）
- [ ] ACC-009 插件声明和管理入口不要求插件/API/配置/状态版本号，不存在版本协商、兼容矩阵或历史接口适配；仅依赖当前契约即可装载和替换实现。（FR-014）
- [ ] ACC-010 无效、乱序、重复配置事件保留最后有效快照；数组覆盖与删除规则有样本断言，旧 Nacos 配置转换后的有效语义经对照验证。（FR-013）
- [ ] ACC-011 工具/能力清单动态变化后，新回合得到新修订；旧回合引用停用插件时被网关拒绝，不继续调用被移除实现。（FR-009/020）
- [ ] ACC-012 供应商 SDK、数据库对象、异常实例或任意宿主属性没有穿过契约边界；worker 与进程内模式使用同一公开业务 schema。（FR-002/005）

## C. 生命周期和资源

- [ ] ACC-013 正式管理入口覆盖完整 load/init/start/stop/dispose/unload；重复相同 operation_id 不重复副作用，非法状态跳转明确拒绝。（FR-007/008）
- [ ] ACC-014 在每个阶段的前、中、后使用受支持的故障注入设置失败/超时；部分初始化资源清理，原正常实现保持或按文档恢复，无关业务仍可用。（FR-009/019）
- [ ] ACC-015 两个管理请求竞争同一实例，两个管理副本竞争同一切换；仅一次 CAS 提交，依赖启停顺序正确，无死锁。（FR-006/008）
- [ ] ACC-016 连续 100 次启停后，任务、定时工作、HTTP/文件句柄、RPC responder、订阅和 UI 注册均回到基线；worker 无残留进程树。（SC-004）
- [ ] ACC-017 停用期间有前台请求、私聊扫描、主动联系、Memory 归并和清理任务，全部纳入排空和取消；60 秒到期明确报告，不能仅检查前台请求计数。（FR-009/SC-007）
- [ ] ACC-018 在 prepared/quiesced/committed/cleaned 各阶段结束宿主进程，重启后只恢复一个有效代次，重复消费无重复写入，旧 worker 重连后的写入被 fencing 拒绝。（FR-008/010）
- [ ] ACC-019 验证进程内逻辑卸载与 worker 物理卸载的报告差异；依赖冲突不能通过替换核心环境包解决，声明需要重启时实际执行并验证影响范围。（FR-017）

## D. 状态、投递与恢复

- [ ] ACC-020 用包含两个人物、共享联系人、不同账号、私聊/群聊/引用、Episode/Atom/文档和未完成发送的状态集完成升级/替换；ID、来源、受众、水位和幂等键保持。（FR-011/022/024）
- [ ] ACC-021 通过正常入口重复投递、重连、扫描补偿和处理中升级，验证会话顺序、归属和单写者；不是手动改内部计数或制造无效状态。（FR-010/018/023）
- [ ] ACC-022 模拟平台接受发送但响应丢失，账本记录结果未知，进入查询或人工处理而非重发；对有查询/幂等能力的平台单独验证确认恢复。（FR-018）
- [ ] ACC-023 Memory 停用与恢复期间保留数据库、KV 和持久 consumer 水位，归并不重复；积压到阈值触发告警/背压，重新启用不额外逐消息调用记忆模型。（FR-011/018/022）
- [ ] ACC-024 数据 migration 在插件私有范围可独立执行，失败不损坏原状态；插件移除不删表，其他插件不能读其私有表。（FR-012/024）
- [ ] ACC-025 演练切换前初始化失败、状态导入失败和切换后故障恢复；候选失败不破坏原状态，恢复按该次变更的联合数据恢复步骤执行，不依赖历史接口适配。（FR-012/SC-008）
- [ ] ACC-026 实际测量联合备份/恢复时间与数据一致性：5 分钟内恢复，已确认持久状态丢失为 0；明确未持久接收平台事件的覆盖限制。（SC-007）

## E. 权限、隔离和故障

- [ ] ACC-027 未鉴权管理操作、未授权工具、跨 AI/账号、越权受众、插件自报身份和模型篡改权限请求被拒绝且有安全审计。（FR-015/025）
- [ ] ACC-028 永久禁用动作在发现和执行路径都拒绝；conditional 执行实际条件，confirm 无确认记录不能执行；工具不能读取/导出凭据。（FR-015/016）
- [ ] ACC-029 权限在排队或执行中撤销后，发出下一项副作用前重新校验；旧能力租约不能复用已失效权限。（FR-015）
- [ ] ACC-030 对不可信测试插件尝试未授权网络、目录、环境、总线 subject 和数据作用域，在实际配置的隔离边界拒绝；普通子进程不被误认成安全隔离。（FR-017）
- [ ] ACC-031 超时、资源过量、worker 崩溃、调用失败触发有界重试、熔断和背压；其他能力的控制组请求全部成功，错误不会被包装成成功。（FR-018/019/SC-003）
- [ ] ACC-032 日志关联插件/实例/代次/配置修订/事件，包含恢复步骤；检查日志和管理导出无凭据值、消息正文或无关私人信息。（FR-013/019）

## F. 项目业务回归与最终门槛

- [ ] ACC-033 从正式 Gateway 启动和本地模拟 NapCat WebSocket/HTTP 入口，验证入站→持久任务→总线→Agent→动作账本→出站完整链路；保留引用、转发、回复对象、白名单和自发消息过滤。
- [ ] ACC-034 24 小时被动私聊、主动联系作息和 QZone 按 AI+person 的关系决策与迁移前一致；NapCat 登录态和已有白名单未被迁移工具覆盖。
- [ ] ACC-035 从真实 Memory 持久订阅及调度入口验证 activity→静默 Episode→Atom→批量合并，不只直接调用 MemoryStateStore 或自定义 repository。
- [ ] ACC-036 GPT-SoVITS/MIMO 及模型故障切换通过正式宿主、当前配置来源和内置插件验证；外部供应商模拟与真实调用证据明确区分，音乐工具当前无真实播放器适配的限制保留。
- [ ] ACC-037 直播导演→场次绑定→Avatar/Stream 订阅/分派/停止回归，停用一个能力不影响无关能力。当前日志占位实现对未接通的外部动作明确 unsupported，不伪报真实舞台/推流成功；以后接入实际驱动时另验其副作用。
- [ ] ACC-038 控制台插件贡献新增、变更、撤销不重新打包核心前端；旧页面调用被停用能力时得到明确不可用状态，登录和历史诊断仍可用。（FR-020）
- [ ] ACC-039 用相同环境、固定外部响应执行 2 AI、20 会话、10 事件/秒、15 分钟负载；记录旧/新 P95、错误、模型调用和 token，符合 SC-005/006。另在获授权的目标环境复验外部依赖耗时。
- [ ] ACC-040 移除所有 migration-adapters 包、旧供应商注册、旧集中配置字段和源码挂载后重复六项硬要求；全部实际插件通过后才宣布整体重构完成。（FR-021/023）
